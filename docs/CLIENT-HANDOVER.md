# 📦 CLIENT HANDOVER — МОНЕТА (vloski.mk)

> **Цел:** Дај му на клиентот (МАК-ФИТ ДООЕЛ / Calivita) **безбеден увид** во инфраструктурата, без ризик да скршат нешто.
> **Принцип:** Клиентот работи САМО преку **МОНЕТА Конзола** (`https://vloski.mk/konzola.html`) — тоа е неговото безбедно алатно за управување. GitHub/Vercel/Supabase се само за увид.

---

## 1️⃣ GitHub — пристап само за читање (Read)

Клиентот добива увид во кодот и историјата, БЕЗ можност за промени.

### Чекори:
1. Одете на **GitHub → вашиот репозиториум** (тој што го хостира сајтот).
2. **Settings** (табот горе десно) → **Collaborators** (во левото мени).
3. Кликнете **Add people**.
4. Внесете ја е-поштата или GitHub корисничкото име на клиентот (на пр. `info@calivita.mk`).
5. Во **поканата** изберете **Read** (само читање) — НЕ `Write`!
6. Кликнете **Add** → клиентот добива покана на мејл и мора да ја прифати.

> ⚠️ **Зошто само Read?** Со `Write` клиентот би можел случајно да објави полуготова промена директно на продуцкија (Vercel автоматски деплоира при push). Со `Read` е невозможно да скрши нешто.

---

## 2️⃣ Vercel — пристап како Viewer (само гледање)

Клиентот ги гледа деплоите, прегледите и користењето — БЕЗ право на промени.

### Чекори:
1. Одете на **https://vercel.com** → најавете се.
2. Отворете го **проектот** `vloski` (или како што е именуван).
3. Таб **Settings** → **Members** (во левото мени).
4. Кликнете **Add Member** (или **Invite**).
5. Внесете ја е-поштата на клиентот.
6. Изберете улога **VIEWER** (само гледање) — НЕ `Contributor` и НЕ `Owner`!
7. Кликнете **Send Invite** → клиентот мора да креира/има Vercel сметка со таа е-пошта и да ја прифати поканата.

> ✅ **Што гледа Viewer-от:** деплои-статус (дали последната промена е жива), прегледни линкови, и **Usage/Bandwidth** во табот **Usage**.
> ⚠️ Viewer не може да менува домени, env променливи или да деплоира.

## 3️⃣ Supabase — ПРЕПОРАКА: НЕ давајте пристап

### Зошто не?
- Клиентот **веќе има се** преку **МОНЕТА Конзола** (`/konzola.html`): производи, цени, попусти, кампањи со датуми, залиха по големини.
- Supabase Dashboard-от е **технички**: еден погрешен клик може да ги скрши RLS-правилата или да избрише табела → сајтот паѓа.
- Анон клучот и лозинката за конзолата се веќе доволни за клиентски потреби.

### Ако клиентот ИПАК инсистира (опција „последна инстанца"):
1. **https://supabase.com/dashboard** → најавете се.
2. **Organization** (горе лево) → **Team** / **Members**.
3. **Invite member** → внесете е-пошта.
4. Изберете улога **READ ONLY** (доколку постои) или најрестриктивна можна — **НИКОГАШ** `Owner` и **НИКОГАШ** не споделувајте го `service_role` клучот.
5. **Никогаш** не го давајте `ADMIN_PASSWORD` (лозинката за конзолата) како Supabase лозинка — тие се различни работи.

> 🔐 **Безбедносна нота:** `service_role` клучот е „master key“ за целата база. Чувајте го САМО вие. Ако некогаш протече — регенерирајте го од Dashboard → Settings → API Keys.

## 4️⃣ UptimeRobot — следење дека сајтот е жив 24/7 (БЕСПЛАТНО)

Најлесниот начин клиентот да знае дека сајтот работи, без да гледа во Vercel/Supabase.

### Чекори:
1. Одете на **https://uptimerobot.com** → **Create Free Account** (или логирајте се).
2. Кликнете **+ Add New Monitor**.
3. Пополнете:
   - **Monitor Type:** `HTTP(S)`
   - **Friendly Name:** `vloski.mk`
   - **URL (or IP):** `https://vloski.mk`
   - **Monitoring Interval:** `5 minutes` (бесплатно) — или 1 мин ако сакате.
4. Кликнете **Create Monitor**.
5. За **известување на мејл**: таб **Alert Contacts** → **Add Alert Contact** → тип `E-mail` → внесете `info@calivita.mk` → **Create**. Потоа во мониторот → **Edit** → додајте го контактот.

> ✅ Ако сајтот падне → клиентот добива мејл автоматски. Ако е жив → ништо не му пречи.
> 💡 Можете да креирате сметка со мејлот на клиентот и да му го дадете пристапот — тој сам си ги гледа статусите.

## 6️⃣ Како да ја следите употребата на ресурси (за ВАС, технички)

### 📊 Supabase (лимити на free tier):
| Ресурс | Free лимит | Наша реална употреба |
|---|---|---|
| База (DB) | 500 MB | ~0,2 MB (20 производи, 158 големини, 8 рецензии) |
| Egress (излезен сообраќај) | 1 GB/мес | Неколку MB |
| Edge функции | 500K повици/мес | Десетици/ден |
| ⚠️ Пауза по неактивност | 7 дена | **Решено** — GitHub Action пика секој ден во 00:00 |

**Каде да се гледа:** https://supabase.com/dashboard → Project → **Settings** → **Usage** (или Organization → Usage).

### 📊 Vercel (лимити на free/Hobby):
| Ресурс | Free лимит | Наша употреба |
|---|---|---|
| Bandwidth | 100 GB/мес | Минимална (статичен сајт) |
| Build минути | 100/мес | Неколку (само при промени) |

**Каде да се гледа:** https://vercel.com → Project → таб **Usage** (или **Activity**).

### ✅ Заштита од пауза на Supabase (веќе активно):
GitHub Action `.github/workflows/supabase-keepalive.yml` прави еден `SELECT` дневно во 00:00 UTC. Доколку поради некоја причина го избришете — **создадете го повторно**, инаку по 7 дена неактивност проектот се паузира и сајтот престанува да ги вчитува податоците.
